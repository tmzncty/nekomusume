## `1a3535b` — H-RUDP-014 byte-accurate Session offsets

Repairs the reviewer H-RUDP-014 finding (reviewer handoff `f40a6c3`):

- Session logical identity is `(SessionId, stream, byte_offset)`; `send_data` advances by
  `payload.len()` with checked arithmetic instead of one per record, so a second record no
  longer lands below `next_receive` and is no longer rejected as a protocol/duplicate error;
- the new offset is committed only **after** the send passed Carrier admission, so a cwnd
  refusal consumes no Session byte space;
- the admitted-send probe size is a fixture field, so a small congestion window is reachable
  deterministically;
- the clean no-loss scenario now uses variable-length records (2,3,1,4 bytes -> offsets
  `0,2,5,6`) and strongly asserts Session truth: four first deliveries, zero Session
  conflicts, zero duplicate suppression, no retained Session error;
- new regression `scenario_cwnd_refusal_consumes_no_session_byte_offset`: fills a small window,
  asserts the refused send returns `None` without recording, then after the ACK frees the window
  asserts the next admitted record still lands on the byte offset the refusal would have used.
  A Session gap or conflict would fail it.

needs either a new bounded diagnostic accessor on the runtime or acceptance of the unit-seam
