## The gap

The existing `json_capabilities_report_every_documented_field` is thorough about
FIELDS - schema string, version, os, arch, `secret_free`, both sub-objects and all
sixteen command entries - but every assertion is a `contains` on a fragment, so
the STRUCTURE between fragments was free. **The capability report could be emitted
as malformed JSON and the whole suite still passed.** All ten of these survived:

- a dropped separator after `target_arch`, `secret_free`, `defaults` or `limits`
- the `commands` array losing its opening bracket
- the closing `]}}` reduced to `]`, given a trailing comma, or given an extra brace
- `secret_free` moved after `defaults`, and `defaults` swapped with `limits`

Consumers parse this report, so a missing separator is a broken contract rather
than a formatting change.

Pinned two ways: the whole stdout line asserted byte for byte against a
constructed expected string (using `env!("CARGO_PKG_VERSION")` and
`std::env::consts` for the environment-dependent fields), which subsumes
separators, ordering and brackets; plus a structural JSON validator (balanced
braces/brackets outside strings, escaped-quote aware, no unterminated string, no
empty-slot patterns) so the test states the real contract rather than only
encoding one accepted string.

## Process note

My first version of the validator asserted `!contains("},")` and
`!contains("],")` as trailing-comma checks. That was simply wrong - `},` occurs
legitimately between array elements in well-formed JSON - and it failed on
**unmutated** code, so it was treated as "I wrote this wrong" rather than as a
kill. A second attempt added `"}]"`/`"}]}"` as forbidden patterns, which are also
legitimate endings and also failed on unmutated code. The check was finally
reduced to patterns that genuinely cannot occur in well-formed JSON, with the
reasoning recorded in a comment. The pre-probe snapshot was verified with md5
equality, a byte-for-byte `diff`, a grep confirming the two expected schema
literals (implementation plus new test) and a grep confirming no scratch residue.
The snapshot/format/parse steps and the probe were separate serialized tool calls.
