## The gap

**No test produced the plain (non-matrix) `client`/`probe` JSON artifact at all.**
`emit_probe` has two JSON branches - with a payload hash and without one - and only
the with-hash branch was exercised, by the benchmark test. The without-hash branch
is reached by any `client --json` that omits `--payload-file`, **and by every UDP
probe**; no test reached it, so every key name and value source in it was free. A
first probe confirmed it: **all six** of its mutants survived.

Also unasserted in the branches that were exercised: the with-hash branch's `ok`
value, its `transport` key and value, and its `elapsed_ms` key; and the human
envelope's labels (`transport=`, `elapsed_ms=`), since only `contains("probe_ok")`
was asserted.

What is now pinned: the no-hash envelope on both TCP and UDP as an exact prefix
plus closing brace around the single varying field (`elapsed_ms`, required to be a
bare decimal); the with-hash envelope end to end (exact head, `elapsed_ms` parsed,
`fd_count` key and value parsed, `wire_bytes:null`, closing brace, nothing but a
newline after); and the human envelope's labels and wiring.

## The one equivalent (measured, not assumed)

`EH_args_elapsed` exchanges the **sources** of the `elapsed_ms` and `fd_count`
fields in the with-hash branch. **Measured to survive.** **Reason**: both are
emitted as bare unsigned decimals into adjacent `"elapsed_ms":`/`"fd_count":` slots,
and the artifact places no magnitude constraint on either, so the exchange is not
observable from the artifact. Pinning it would require asserting a
machine-speed-dependent inequality - the observed values in one run were
`elapsed_ms`=193 and `fd_count`=5, but `elapsed_ms` may legitimately be small, so a
magnitude assertion would be fragile rather than stronger. Reported as an
equivalence, not claimed as coverage. All other mutants in the round were killed.
