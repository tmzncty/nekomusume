## The one equivalence (verified by argument and by measurement)

`LV_created_future_off` removes `now_ms < state.created_at_ms` from `live`.
`last_progress_ms >= created_at_ms` holds invariantly - both are set to the admit
time and `last_progress_ms` only advances after `live` itself passes - so
`now < created_at` implies `now < last_progress`, and the progress clause already
rejects every reading the created clause would. Measured by applying the mutant
with a scratch test that drove clock readings from the admit time upward and
across a window rollover: every reading stayed rejected. The scratch was removed
and the worktree restored, md5-verified against the snapshot, before the final
probe.
