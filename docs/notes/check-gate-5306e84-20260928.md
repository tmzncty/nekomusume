## Slice scope

Test-harness robustness repair, **not** a coverage slice: no new assertion and no
mutation claim. +38/-4 in `crates/neko-cli/tests/multistream.rs`; the 4 deletions are
original `let mut server` bindings that lost their now-unneeded `mut`. No source

### Problem

Four tests spawn a `multistream --mode server`, do client-side work (connect, frame
I/O, assertions), and only then reap it in `bounded_wait_with_output`. A panic in that
window unwinds past the reap, and `std::process::Child` does not kill on drop. The
still-listening server is reparented to init and outlives the test.

This was observed in practice once (recorded in `check-gate-2dbff09-20260928.md`):
after a mutation-probe run, a server survived about 19 minutes holding
127.0.0.1:37649. It only happens when a test is already failing, so it never hid a
failure. It does leak a listening port and a process across runs.

### Fix

`ServerGuard(Child)` with `Deref`/`DerefMut` and a `Drop` that runs `kill()` then
`wait()`. Each server spawn is shadowed into a guard right after `spawn()`.
`bounded_wait_with_output` and every assertion are untouched. On the normal path the
child is already reaped, so `kill()` returns a harmless error and `wait()` returns the
cached status.
