## The two equivalences (unreachability, not "the test passes")

- `E_data_huge_ge`: shifting the Data arm's `record.data.len() > u16::MAX` check
  to `>=`. The u16 check is evaluated first, but `encode`'s encoded-size gate
  (`> PROCESS_FRAME_MAX`, i.e. 4096, far below `u16::MAX`) refuses any payload
  large enough to reach that comparison, with the same `TooLarge` error - so the
  two forms are indistinguishable. My first version of the test asserted the u16
  edge directly and **failed on unmutated code**, which is how the shadowing was
  found.
- `E_ack_len_overflow`: `u64::try_from(usize).map_err(..)` replaced by
  `.unwrap_or(0)`. On this 64-bit target the conversion cannot fail, so the
  error arm is unreachable.
