## What this commit does

Tightens the timing in `non_ack_eliciting_ack_does_not_reset_pto` so the
non-ack-eliciting ACK (largest=1) no longer time-thresholds the still-unresolved
ack-eliciting packet 0 before the final `pto_count` reset assertion. Previously
packet 0 was silently retired as a time-threshold loss, so the "ACK for the
ack-eliciting packet resets the streak" assertion could pass without packet 0
ever being outstanding. The test now asserts packet 0 remains in flight after
the non-eliciting ACK and uses packet timings that keep loss_delay above
packet 0's age.

This is a test-only change to `crates/neko-reliable/src/lib.rs`; no production
recovery/ACK/PTO semantics changed. It is orthogonal to the H-I4-119 maintainer
semantics gate (which remains undecided policy, not auto-patched).
