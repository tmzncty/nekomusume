## The three equivalences (each verified empirically, not argued)

- `SS_seal_trunc_off` - dropping `out.truncate(8 + n)`. Measured with a scratch
  test: the sealed record still comes out at exactly
  `8 + RECORD_CONTEXT_LEN + MAX_RECORD_PLAINTEXT + 16` bytes, because
  `write_message` returns a length that fills the buffer exactly. The truncate is
  a no-op.
- `SS_open_min` - relaxing the 24-byte floor to 16. Measured: inputs of 16..23
  bytes still return `SessionRejected`, because the AEAD read refuses them. Same
  error class, nothing observable.
- `SS_open_replay_before` - moving `replay.accept` before the context check.
  Measured on a deliberately context-mismatched pair: every sequence is
  uniformly rejected and repeating one stays rejected, so no sequence number is
  ever "freed" observably. Sequences only repeat after a rekey, and a rekey
  resets the window on both sides, so the ordering has no reachable consequence.

All three scratch experiments were removed and the worktree restored
(md5-verified) before the final probe.
