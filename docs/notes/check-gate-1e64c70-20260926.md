The invalid constructions are not equivalences and are recorded as such:

The three equivalences are argued from source, not from absence of a test:

- health_window: reporting `max_ignored` instead of `ignored` in the
  budget-exhausted error. The guard at the only return site is
  `ignored == max_ignored`, so both expressions hold the same value; the
  pre-existing test asserts `ignored: 1_024` with max_ignored 1_024.
- lifecycle: `>=` for `==` against ALL_PREREQUISITES. The mask is only ever
  OR-ed with the five single-bit values 1,2,4,8,16, so reachable values are
  at most 31 = ALL_PREREQUISITES; the two comparisons agree for every reachable
  value, and the sibling `>` mutant is killed, which is consistent.
- reachability: the observation-time fallback string. It is only produced when
  `SystemTime::now().duration_since(UNIX_EPOCH)` fails (pre-1970 clock, an
  unsupported configuration), and the pre-existing stability test parses that
  field, so a non-numeric fallback would fail there rather than pass silently.

Two harness corrections: three anchors (two reachability, one lifecycle)
initially matched more than one source site because the new assertions contain
the same literals; they were narrowed to the format string's escaped context so
each mutant is a genuine single-site edit.
