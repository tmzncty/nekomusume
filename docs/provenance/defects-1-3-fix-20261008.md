## #1 UDP probe client parks for the whole duration on a lost response

**Re-characterization (measured):** the defect was NOT an unbounded hang.
`set_read_timeout(d)` has existed since the first commit (a6e1437); the
socket read timeout equaled the whole `--duration`, so a lost response
parked the client for the FULL session inside one recv (measured: 8.3s
blocked with duration=8, 20.5s with duration=20) and the documented
failure classification never fired in practice.

**Fix:** every client-side UDP wait on that socket — negotiation response,
handshake response, and per-exchange echo — now goes through one
`recv_bounded` helper: 100 ms poll granularity (the established pattern at
main.rs's other UDP paths), a 3-second per-wait cap (the failover command's
`secs.min(3)` recovery-wait convention), clamped by the session deadline
`start + d`. Lost responses surface a classified `fail()` exit in seconds.

**Measured:** 100% s2c loss via tools/impair-proxy (seed 11): blocked
20s → **3.02s** (rc=2, `deadline elapsed before response`).

**Red→green:** `defect_regressions::udp_echo_loss_exits_within_deadline_window`
spawns the real binary through impair-proxy with --duration 20 and asserts
exit within 12s; red on the unfixed tree (parked full duration), green at
3.0s on the fixed tree.

## #3 periodic payload ceiling: CLI claimed 1200, runtime allows 1170

**Boundary (measured + derived):** a periodic payload is wrapped in a
`ProcessMessage::Data` frame before `seal_unreliable`, so the enforceable
payload bound is `MAX_UNRELIABLE_DATAGRAM − PROCESS_DATA_HEADER_LEN` =
1200 − 30 = **1170**. Identical-pair measurement: 1170 green, **1171
client core-dump (rc=134, seal unwrap panic)**; the CLI config layer
validated against the raw 1200 and let 1171..1200 through to the panic.
(local-limits' untested 1166–1171 gap is now closed: 1166–1170 pass,
1171 aborts pre-fix.)

**Fix:** `PERIODIC_BYTES_MAX = MAX_UNRELIABLE_DATAGRAM −
PROCESS_DATA_HEADER_LEN` (compile-time `const _` pin = 1170) is now the
config-layer ceiling in both default and measurement modes ("bytes
outside 1-1170"), the seal unwrap is a classified `fail("payload too
large")` instead of a panic, and `capabilities` states the real number:
JSON gains `"periodic_bytes_max":1170` beside `bytes_max:1200` (the UDP
probe payload bound is unchanged — probe payloads are not framed); the
human limits line gains `periodic_bytes=1-1170`.

**Red→green:** `defect_regressions::periodic_bytes_validation_uses_the_
sealed_frame_ceiling` (1171/1200 rejected by name in both modes; 1169/1170
pass validation) and `defect_regressions::capabilities_report_the_true_
periodic_bytes_ceiling`. The capabilities exact-line pin and one
measurement-mode pairing test were updated to the new contract (1200-based
pairings now use 1170; the 32 MiB ceiling test uses 1170×28681).
