## 3.1 入向方向性专节（美国→大陆 0.1Mbps 级）

三条美国腿（us-209/vps-104/faraway）→ bjlh 40200 端口入向全塌至 0.09–0.16 Mbps（nc 窗口法：固定时长窗口收到的字节数），同期出向 36–50 Mbps 正常，faraway→bjlh RTT 163ms/ICMP 通：
- **方向性而非路径性**：同路径反向（大陆→美国）即正常，说明不是运营商间链路容量问题，是入向方向策略（拥塞/限速特征）。
- **V6 部分避开**：hk→faraway V6 14.3 vs V4 23.2（HK 出向），tmzn→faraway V6 26.3 vs V4 36.8（家宽出向）——V6 全程可用无塌陷；入向 V6 腿因 bjlh 安全组未放 40201 未测，方向性主备思路：国际→大陆流量选 V6 或经中转入口。
- **单连接无解，多流（≥4）有解**：这是网络层方向性策略——per-connection 实锤（见下条）后精确化：协议特性不改变单连接入向容量（R1 已在干净路径验证 +17.4%，量级不解决入向塌）；多流（≥4 并行连接）可恢复到 ~200 Mbps 级。部署含义：国际→大陆单连接场景选 V6/中转，多连接场景直接多流。
- 对比 XJ 联通入向病（0.04–1.93 Mbps 不稳）：同一方向性家族（大陆入向普遍受限），XJ 更重（连 bjlh 腾讯方向也病）。本矩阵美国腿只测了到 bjlh 一类目标，「美国→大陆」结论限于腾讯北京目标类。

## 5. 流程坑（记档）

1. **bulk 端口域硬编码 40080–40100**：不是任意高端口；`--port` 必须落此区间，否则 config 拒绝。
2. **bytes-total 必须整除 stride**：1170 档 stride=1170、大档 stride=tier−18；256MiB(268435456) 不整除 1170，用 268435440（1170×229432）。
3. **keygen 输出的是 client 身份公钥**：server 公钥看 server 启动日志 `server_public_key=` 行；错配时 server 报 `unauthorized handshake`，client 报 `handshake response failed`。
4. **pkill -f 自杀 ssh 包装 shell**：`pkill -f bulk-server` 会匹配携带同样字符串的 bash 包装层导致 ssh 命令自杀；用 `pkill -x neko-cli-head`。
5. **nc -l 单连接探针陷阱**：探测端口可达性会消耗掉 nc -l 的唯一连接（监听即死）；用 `nc -k` 持久监听，探测与测试不可混用同一次监听。
6. **XJ/Windows 侧 ps1 教训沿用**（见 p4d-mesh 文档）：经 ssh+cmd.exe 调 PowerShell 时 `;` 污染参数，须 -File 跑 ps1。
