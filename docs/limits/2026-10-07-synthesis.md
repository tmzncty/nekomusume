# 猫娘协议极限测试 — 总报告（三役合璧）

2026-10-07 · 佩丽卡（Overseer）汇总 · 数据来源：docs/limits/ 下三份脱敏报告 + private/ 原始数据

## 一句话答案

**猫娘协议库本身有界、稳、抗丢包；它的"极限"目前全部卡在 CLI 测试工具（fixture）的节奏语义上——是节奏测量仪，不是带宽测量仪。协议真实吞吐上限尚未被触及，要测到它需要一个连续发送的负载入口（见"下一步"）。**

## 三个数量级的故事

| 层 | 实测 | 含义 |
|---|---|---|
| 协议库硬上限（代码内） | 单会话 64MiB / 65,536 records / 4,096B 帧 | 安全防线，460 条断言保护 |
| CLI fixture（TCP） | 交换周期 = 3.4×RTT+40ms；1150B 记录折合 1.6–27.7 KiB/s | stop-and-wait 语义天花板，**非协议上限** |
| HY2 同路径对照 | 75–206 Mbps（四路径 MD5 全一致） | 差距三个数量级 = fixture 语义，不是库 |

## 各轴极限一览

| 轴 | 极限值 | 备注 |
|---|---|---|
| 抗丢包（TCP） | **无断点**（本机 ≤70%、公网 11.67% 全通过） | 握手期例外：30% 丢包+5s 窗口即败，30s 窗口恢复 |
| 抗丢包（UDP probe） | 存活率 = (1-2p)^n；单包丢失即 hang | 缺陷 #1 |
| 延迟 | RTT<83ms 免费；>83ms 线性劣化 | delayed-ACK 重叠 |
| 并发流 | 1–256 完全平坦（12.15 ex/s） | server 串行处理，流数不是瓶颈也不是增益 |
| 长稳 | 1h + 58min soak 双绿，RSS 恒定，零重连 | count 上限先于字节上限触顶 |
| 换端口（NAT rebind） | 即死 | 缺陷 #2 |
| MTU 黑洞 | TCP 无感；UDP 可诊断不自愈 | 缺陷 #4 |
| 时段效应 | 凌晨满速 ↔ 白天 11.67% 丢包摆动 | 全数据点带时段戳 |
