## `901991d` — prove a PTO-only health sample cannot erase a later resolved loss

New regression `path_recovery_tests::pto_only_health_sample_cannot_erase_a_later_resolved_loss`
covers the H-RUDP-001D reviewer-mandatory cases 1 and 4:

1. four packets are sent;
2. a PTO that schedules probe frames emits one fresh health sample reporting `0` loss — it
   resolved no packets, so there is no loss to report;
3. with no intervening send, a later ACK retires one packet and newly declares older packets
   lost;
4. the resulting sample must use the resolved denominator `1 acked + N newly lost` and report
   non-zero loss.

Under the removed send-time denominator that same interval had `delta_sent == 0` and was
reported as a falsely clean `0/mille` sample — the exact defect H-RUDP-001D identified. The
expected ratio is derived from the public `packets_lost()` delta rather than hard-coding the
recovery reorder policy.
