## Why P2 remains open

The handoff required a positive built-binary proof that the post-return path executes and settles both evidence domains. The current test still deliberately ignores both process exit statuses and explicitly tolerates the fixture never reaching post-return. Therefore the new assertions can all be skipped and the test can pass without exercising the property P2 exists to prove.

Additional acceptance gaps remain:

1. **No positive process completion requirement.** Client/server success are still not asserted.
2. **No non-vacuous post-return requirement.** `r9_udp_post_return_sent` is an optional guard rather than required evidence.
3. **No exact server ordering proof.** There is no structured proof that successful `SessionRuntime::receive` precedes creation/emission of both the Session DeliveryAck and Carrier packet ACK.
4. **No exact Session confirmation identity.** `udp_return_delivery_ack_validated` does not bind the applied confirmation to `stream=1, offset=32`.
5. **Settlement evidence is not post-return scoped.** A generic `remaining_in_flight=0` substring can be satisfied by an earlier recovery-settlement event; it is not a dedicated terminal post-return proof.
6. **Only one acknowledgement order is exercised.** The required Session-ACK-first and Carrier-ACK-first cases are still absent; no bounded post-return reorder seam exists.
7. **No explicit domain-separation regression.** The test does not prove Session DeliveryAck cannot substitute for Carrier settlement or vice versa.
