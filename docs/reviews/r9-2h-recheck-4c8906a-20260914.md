## HIGH H-R9-010 — partial Carrier settlement still emits a success-looking settled event

Current `failover_client` still performs:

1. a logical-confirmation loop while `!outstanding.is_empty()` using `application_deadline`;
2. a later Carrier settlement loop while `rt.in_flight() > 0`.

Inside the settlement loop, any `recv_udp_delivery_ack` error executes `Err(_) => break`. After that break, the caller unconditionally emits:

- `r9_udp_packet_ack_outcomes` with the remaining in-flight count; then
- `r9_udp_in_flight_settled` with the same remaining in-flight count;

and continues into health/failover code.

Therefore timeout, receive failure, or malformed-budget exhaustion can leave authoritative Recovery state nonzero while the event name still says `in_flight_settled`. Downstream R9 logic can then run on a false settlement premise.

### Required invariant

The reliable receive operation has one success condition only:

```text
outstanding Session confirmations are empty
AND
ReliableUdpRuntime::in_flight() == 0
```

Before both are true, timeout / receive failure / malformed-budget exhaustion is an explicit bounded failure or partial result. It must not emit `r9_udp_in_flight_settled`, and downstream health/failover logic must not consume a successful-settlement premise.

### Recommended minimal implementation shape

Do not add another decoder or policy value. Collapse the caller ownership into one bounded operation helper/state object that owns for the entire operation:

- the outstanding logical-record set;
- the existing absolute application deadline;
- the persistent malformed counter;
- Carrier ACK applied/rejected counters;
- logical confirmation count;
- access to the one `ReliableUdpRuntime` owner.

Its loop condition is exactly:

```text
while !outstanding.is_empty() || rt.in_flight() != 0
```

Each authenticated plaintext still goes through the existing classifier exactly once. Session DeliveryAck applies `SessionRuntime::delivery_ack` for the exact matched record; Carrier ACK applies only Recovery feedback; bounded negatives consume the same malformed counter. Any error before the loop condition becomes false returns a typed incomplete/error result and stops this R9 operation. Only the complete return path may emit `r9_udp_in_flight_settled`.
