## Invariant challenged

A retransmission must be built/sealed before congestion admission, and the exact encoded/sealed byte count must be used for both `can_send` and Recovery ownership accounting. A refusal must not commit retransmit ownership, send a socket datagram, emit `r9_udp_retransmit_sent`, or fabricate Session state. The negative regression must fail if the executable caller regresses to checking retained plaintext length instead of encoded wire length.

## Result

Current source satisfies the ordering: post-return retransmission encodes/seals first, checks `rt.can_send(re_sealed.len() as u64)`, then calls `on_retransmit_sent(..., re_sealed.len() as u64, ...)`, and only afterwards performs `send_to` and emits `r9_udp_retransmit_sent`. `9a113f2` applies the same exact-wire ordering to `lab_pump`.

However `4a6f52d` does not exercise that caller or encode/seal anything. It fills cwnd with synthetic 400-byte Recovery sends and then directly asserts `!rt.can_send(400)`. Its own comment says it is "simulating the caller's gate"; it never compares retained plaintext length against a larger encoded/sealed length, never invokes the executable retransmit path/helper, and contains no real socket-send or diagnostic observation. Therefore the test would still pass if `main.rs` regressed from `can_send(re_sealed.len())` back to `can_send(plaintext.len())`.

The current source repair remains accepted; the claim that H-R9-041 has an acceptance-grade discriminating refusal regression does not.

## Smallest repair contract

Keep the `9a113f2` implementation semantics. Add a focused deterministic regression against the real retransmit admission owner (direct executable path or a minimal helper shared by it) such that:

1. using existing congestion/accounting values, `retained_plaintext_len < remaining_send_budget < encoded_wire_len`;
2. the real path builds/seals first and refuses on the exact encoded/sealed length;
3. refusal commits no `on_retransmit_sent` ownership/state, performs no datagram send, emits no `r9_udp_retransmit_sent`, and creates no Session delivery transition;
4. a paired control with sufficient admission budget proceeds using the same encoded-byte count for admission and Recovery accounting;
5. the test would deterministically fail if the caller were changed back to plaintext-length admission.

No new cwnd/capacity/security policy value is needed. No wire/crypto architecture change is authorized or required.

H-R9-042 remains dependency-ready immediately after this discriminator closes. No new live/WAN question is created; `READY_LIVE: none` remains appropriate.
