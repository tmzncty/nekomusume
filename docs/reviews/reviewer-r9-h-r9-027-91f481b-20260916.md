## H-R9-027 — HIGH acceptance/evidence false positive

Both new process seams miss the exact semantic branches they claim to test.

### A. `--send-stale-ack` replays ciphertext, so crypto rejects it before Recovery can return accepted-empty

The server creates one authenticated `sealed_ack`, then `--send-stale-ack` sends **that exact ciphertext** and the normal path sends the same `sealed_ack` again.

`SecureSession::open_unreliable` delegates to `open`; after AEAD/context validation, `open` calls the bounded `ReplayWindow::accept(sequence)`. A second copy with the same authenticated sequence is rejected as replay and collapses to `SessionRejected` before plaintext reaches `ProcessMessage` / wire ACK classification.

Therefore the duplicated datagram cannot exercise the intended H-R9-026 branch:

```text
canonical Carrier ACK accepted by crypto
  -> Recovery accepts stale/duplicate ACK
  -> Ok(RecoveryResult { acked_packets: [] })
  -> UdpAcknowledgement::Carrier { applied:false, rejected:false }
```

Instead it exercises the crypto replay negative. The current test only asserts that no `r9_udp_packet_ack_rejected` string appears and that the real operation later settles; a crypto-rejected replay satisfies those assertions without ever producing accepted-empty Recovery feedback.

**Smallest repair:** send the same canonical ACK **plaintext semantics under a fresh authenticated envelope/sequence**, not the same ciphertext. The first canonical ACK must retire real packet ownership; the freshly sealed second ACK must pass crypto and reach the same primary Carrier ACK owner after that retirement, yielding `Ok` with empty `acked_packets`.

The focused oracle must prove the duplicate itself:

- was injected as a fresh authenticated record and consumed by the same owner;
- caused zero additional positive Carrier retirement;
- caused zero rejection event/counter;
- caused zero Session logical confirmation/watermark mutation;
- left Recovery/Session accounting equal to the state established by the first real ACK.

A test-scoped accepted-empty classification diagnostic is acceptable if it is explicitly diagnostic and never represented as delivery/packet-transition evidence. If lower-level deterministic tests already prove the state invariance, the process fixture may focus on owner classification plus exact transition cardinality.

### B. `--send-future-ack` uses an empty ACK range, so it rejects before the `largest > largest_sent` guard

The new future seam constructs:

```text
largest_observed = u64::MAX
ranges = []
ack_delay_us = 0
```

The authenticated receive owner decodes the wire `AckPayload`, converts only `ack.ranges` into `neko_reliable::AckRanges`, and passes those ranges to `ReliableUdpRuntime::apply_ack`.

Exact-current `Recovery::on_ack` begins with:

```text
let largest = ack.largest().ok_or(Error::InvalidRange)?;
```

Only after a nonempty range maximum exists does it compare that maximum with `largest_sent` and atomically reject future/never-sent feedback before RTT/loss/PTO mutation.

So the current empty-range fixture is rejected by the generic **empty AckRanges** precondition. The wire field `largest_observed=u64::MAX` is not what reaches `Recovery::on_ack` as its `largest`. The process test can observe `r9_udp_packet_ack_rejected` and pass without exercising candidate A at all.

**Smallest repair:** encode a nonempty canonical range naming a definitely never-sent packet, e.g. `[u64::MAX, u64::MAX]` with `largest_observed=u64::MAX`, or another value deterministically proven greater than the sender's `largest_sent`. The range maximum passed to Recovery must itself be future/never-sent.

Make the injection one-shot/deterministic so the test can require exact cardinality rather than "at least one" rejection. Then require:

- exactly one typed future rejection attributable to that injection;
- zero false positive Carrier transition from it;
- legitimate ACKs can still settle the real packets;
- the operation-wide Session state is unaffected by the rejected feedback.

Add or reuse a focused deterministic `Recovery` / `ReliableUdpRuntime` regression that snapshots existing observable state before the future ACK and proves it is unchanged after `InvalidRange`: in-flight/sent ownership, RTT estimator, PTO count, loss/retransmit outcome and Reno accounting where exposed. Do not invent production observability solely for already-testable internals, and do not incorrectly require every acknowledged packet number to remain in the sent map.
