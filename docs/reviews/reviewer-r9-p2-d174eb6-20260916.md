## HIGH H-R9-026 — the shared ACK owner still collapses accepted-empty and rejected Carrier feedback

H-R9-025 required three distinct semantic classes at the shared authenticated receive owner:

1. canonical Carrier ACK accepted but no recovery transition (stale/duplicate empty outcome);
2. canonical Carrier ACK accepted and one or more packets actually retired;
3. typed recovery rejection/error (for example future/never-sent ACK).

Exact `d174eb6` still collapses classes 1 and 3.

Current code performs:

```text
let outcome = rt
    .as_deref_mut()
    .map(|r| r.apply_ack(&ranges, 0, ack.ack_delay_us).ok());
let acked_packets = outcome
    .flatten()
    .map(|o| o.acked_packets)
    .unwrap_or_default();
let applied = !acked_packets.is_empty();
return Ok(UdpAcknowledgement::Carrier { applied, acked_packets });
```

`Result::ok()` erases `PathRecoveryError`. Therefore:

- an accepted duplicate/stale ACK that returns `Ok(RecoveryAckOutcome { acked_packets: [] ... })` becomes `Carrier { applied: false, acked_packets: [] }`;
- a future/never-sent ACK that `Recovery::on_ack` rejects atomically with `InvalidRange` also becomes the same `Carrier { applied: false, acked_packets: [] }`.

The distinction is real and already part of current committed recovery semantics: duplicate/stale feedback may be accepted with an empty resolved outcome, while `largest > largest_sent` is rejected before RTT/loss/PTO mutation.

This ambiguity leaks into callers. Existing initial/settlement callers interpret `applied == false` as `packet_ack_rejected`, so a valid accepted-empty duplicate can be mislabeled as a rejection; conversely a genuinely rejected future ACK no longer has a typed rejection outcome at this owner. The post-return path no longer produces the false positive fixed by H-R9-025, but the owner still cannot prove whether `applied=false` means accepted-empty or rejected.

This is a correctness/evidence HIGH because R9 process/result truth and the later R9-5 adversarial-feedback lane require exact separation between accepted-empty and rejected feedback. R9-3 expansion remains blocked until the owner preserves that distinction and focused regression exists.
